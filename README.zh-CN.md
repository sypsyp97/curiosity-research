# curiosity-research

[English](README.md) · 简体中文

给 [Claude Code](https://claude.com/claude-code) 的好奇心驱动深度调研,一个 workflow 脚本。
它全程维护一个**当前答案**,并把 agent 预算花在最可能改变这个答案的地方。

```
写下先验 ─→ ┌─ 探索 ─ 阅读 ─ 审计 ─ 复盘 ─┐ ─→ 带引文的报告
            └──── 每轮重新瞄准的目标是 ────┘
                  「什么会改变当前答案」
```

> **状态:正在积极开发。** prompt、旋钮和遥测经常变——需要稳定就锁一个 commit。

## 内置的那套

四个问题,读它源码 + 实跑量出来的(以撰写时的版本为准):

- **只有一趟。** 报告 schema 里有 `openQuestions` 字段、综合 agent 也会填,然后 workflow 直接返回。
  发现的新问题永远不会变成新的检索。
- **审核会删掉单一来源的事实。** verifier 被要求「不确定就默认判否」,三票里两票就杀掉一条 claim。
  而「从某个仓库配置文件里读出的默认值」天然只有一个来源,无法独立佐证,于是被删。
- **没有域名级配额。** fetch 去重是按 URL 的,所有 fetch 槽位可以全落在同一个内容农场。
- **成本没有上限。** 架构上会展开到 97 个 agent(某道题实测 96),其中约四分之三是审核投票。

## 这套怎么做

- **对答案的信念,每轮更新。** 一个 assessor 重述当前最佳答案、写下什么会改变它,并据此瞄准下一轮。
  它可以提前收工——而当队列里还有高分线索、有阻塞性缺口或未裁决的矛盾时,**harness 会否决它的「收工」**。
- **好奇心 = 预测误差。** 每条检索线在检索**之前**先写下预期;surprise 是拿来源和这条预期做**比较**
  (矛盾 / 超出 / 一致 / 没提),继承给它派生的后续线,并随深度冷却:
  `score = 重要性 × 新颖度 × 站点偏好 × (0.4 + surprise · decay^深度) / 成本`。
  打脸先验的线自动升到队首,证实先验的线自动沉底。
- **矛盾插队。** 两条检测路径——harness 侧把 `subject|measure` 规范化后做**完全相等**匹配(零假阳),
  加上 assessor,它是全流程唯一看得见整张 claim 表的角色。裁决时必须先排除口径、协议、版本差异,
  才允许把一件事叫做真矛盾。
- **审计要保证引文指向真处。** 每条 claim 都去被引来源里**机械核对**那句引文,按来源分组、一个 agent 一页
  (成本在打开页面,不在多找几条)。只有引文**根本不在**来源里、或被更强的一手来源直接反驳才杀;
  来源弱、过时只降一档置信度。否定命题(「X 从来没报过 Y」)靠**在源头确认缺席**来通过。
  被杀掉的 claim 对 assessor 直接不可见。
- **预算就是契约。** 一个硬 agent 上限,每次派活前检查。审核票数由它反推(先覆盖后深度),
  60:40 的覆盖/好奇心分账保证报告最后真的回答了被问的问题,探索没花完的额度回流给审计。
- **遥测不许自夸。** 审计覆盖率、每轮新增 slot 数、退化的 assessment、被丢弃的信念更新、引文挂错数、
  以及报告引用运行者本地笔记的次数,全部计数并上报。其中好几个计数器的存在,
  正是因为早先版本谎报过自己干了什么。
- **为便宜模型设计。** 所有角色钉死 sonnet。URL 由 harness 指派、从不问模型回忆;
  网页文本进 prompt 一律围栏包起来当数据;判断一律用比较句提问,不问「你感觉如何」。

## 实测

和内置那套等预算 A/B(同样 30 个 agent 上限、同样模型、同一道题、同一天):

|                        |    内置(加盖) | curiosity-research |
|------------------------|-------------:|-------------------:|
| 实际用掉的 agent        |        29/30 |              30/30 |
| token                  |       1.61 M |             1.78 M |
| 墙钟                   |   **519 秒** |            1706 秒 |
| 打开的来源             | 10(19 个没预算打开) |        **12** |
| 四个子问题答了几个     |        2 / 4 |          **4 / 4** |
| 人工逐条核对存活的结论 |          1/3 |            **6/8** |
| 引文挂错              |            0 |                  0 |

同样的预算下它更慢、略贵;换来的是覆盖率,和经得起核对的结论。

## 安装

```bash
mkdir -p ~/.claude/workflows
curl -fsSL -o ~/.claude/workflows/curiosity-research.js \
  https://raw.githubusercontent.com/sypsyp97/curiosity-research/main/curiosity-research.js
```

开一个新的 Claude Code 会话,然后说:

> 用 curiosity-research workflow 查一下:*你的问题*

需要 Claude Code 带 Workflow 工具、WebSearch 和 WebFetch。配置从 `args` 传:
`agents: 12` 约等于快速核查,`30` 是默认报告档,`60` 是穷举;`verify.mode: "kill"` 可切回内置那套
「多数判否就删」的审核行为。workflow 名字是按会话缓存的——**改完文件要重开会话,或者用 `scriptPath` 调用**。
