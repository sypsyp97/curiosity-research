# curiosity-research

[English](README.md) · 简体中文

给 [Claude Code](https://claude.com/claude-code) 的深度调研 workflow，一个文件。

你问它一个问题。它先写下自己目前的答案，然后专门去查那些**有可能推翻这个答案**的地方；
查到再查也不会改变答案了，就停。

```
先猜 ─→ ┌─ 搜索 ─ 阅读 ─ 核对 ─ 复盘 ─┐ ─→ 带引文的报告
        └──── 每轮都瞄准「什么能 ────┘
              推翻现在的答案」
```

> **正在积极开发。** prompt 和参数经常改——要稳定就锁一个 commit。

## 安装

```bash
mkdir -p ~/.claude/workflows
curl -fsSL -o ~/.claude/workflows/curiosity-research.js \
  https://raw.githubusercontent.com/sypsyp97/curiosity-research/main/curiosity-research.js
```

需要 Claude Code 带 Workflow 工具、WebSearch 和 WebFetch。

## 用法

开一个新的 Claude Code 会话，然后说：

> 用 curiosity-research workflow 查一下：*你的问题*

参数从 `args` 传。`agents` 定预算——`12` 快速核查，`30` 常规报告，`60` 穷举。
`verify.mode: "kill"` 把核对切回内置那套「有疑就删」的行为。workflow 名字按会话缓存，
所以改完文件要重开会话，或者用 `scriptPath` 调用。

## 行为

- 每轮都重新写一遍「目前的答案」和「什么会改变它」，下一轮就照这个去查。它可以提前收工，
  但只要还有强线索、已知的空缺、或者两个来源互相矛盾，就不许收。
- 搜之前先写下自己预期会看到什么。跟预期**相反**的来源优先追下去，证实预期的往后排。
- 每条结论都会重新打开被引用的那个网页，去找那句原话。找不到的直接删；来源只是弱一点
  或者旧一点，就只降低可信度。「没有人报过 X」这种说法，靠去源头确认 X 确实不存在来通过。
- 一个数字管住 agent 总数。核对几条、挖多深，都从这个数字推出来；探索没花完的额度自动
  转给核对。
- 它对自己不撒谎：核对了几条、几条引文是错的、因为预算不够放弃了什么，都会报出来。
  其中好几个计数器之所以存在，就是因为早先的版本在这里出过错、悄悄把自己的工作说大了。
- 它假设用的是便宜模型。所有 agent 都跑 Sonnet：一个 agent 只干一件事，网址是直接递给它
  而不是让它回忆，判断一律让它做比较，而不是问它「你感觉怎么样」。

## 实测

同一道题、同一天、同样 30 个 agent 的预算、同样的模型：

|                        |          内置 |    这套 |
|------------------------|-------------:|--------:|
| 用掉的 agent            |        29/30 |   30/30 |
| token                  |       1.61 M |  1.78 M |
| 耗时                   |   **519 秒** |  1706 秒 |
| 真正打开的网页          | 10（19 个因预算没打开） | **12** |
| 四个子问题答了几个       |        2 / 4 | **4 / 4** |
| 人工逐条核对后站得住的结论 |        1/3 | **6/8** |
| 引文指错网页            |            0 |       0 |

同样预算下它更慢、稍贵。换来的是覆盖面，和经得起核对的结论。
